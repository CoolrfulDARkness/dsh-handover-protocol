# HANDOVER-PROTOCOL — 交接协议 V1.1（触发词驱动，通用版）

> 版本：V1.1 / 2026-11-20。全文 SHA 见文末自标识。
> 适用：**任何智能体、任何项目、任何会话**——只要收到触发词即执行，不依赖记忆、不依赖项目配置。
> 上位文件：完整论证与业界对照见 `.tmp\HANDOVER-STANDARD-DRAFT.md`（V1.1）；本文件是可独立执行的操作版。
> 证据与对抗记录：HANDOVER-EVIDENCE.md（四来源 GitHub 实证）、HANDOVER-ATTACK.md（18 攻击/3 BLOCK 已修）。

## 0. 触发词映射（本协议的唯一入口）

| 你听到/看到 | 你的身份 | 立即执行 |
|---|---|---|
| "准备交接" / "交接" / "收尾" / "我要下线了" | **移交方** | §二 移交手续 |
| "你来接手" / "接手" / "接管" / "继续前任的工作" / "你接替它" | **接管方** | §三 接管手续（第 0 步=分级自判，fail-closed） |
| 两种都没听到 | 普通 agent | 不适用本协议；但 §一 的日常增量动作（1 分钟/轮）仍建议执行，它是事故交接的唯一保险 |

判定歧义规则：消息同时含两种语义（如"你接手，然后交接给别人"）→ 先按接管方做完 §三，再按移交方做 §二。无法判定 → 向发话方确认，不猜测。

## 一、日常增量（移交准备的事实基础——每轮 1 分钟，事故保险）

1. 产物随产随归档 + 记 SHA（不依赖会话记忆；没落盘 = 不存在）。
2. 台账/工作文档**只追加不重写**（新信息进新时间戳节）；每节末尾记**节级 SHA**。
3. 每轮更新三行：横幅状态一行、未验项入册、**运行态登记**（在途轮次/后台 job/定时任务：谁、目标、预计何时结束）。
4. 结论必带强度标注 `[实测]/[构造式]/[推导]/[未验]`；数字必带四件套（装置 SHA + 原始数据路径 + 样本数 + 环境快照）。

## 二、移交手续（触发后执行）

**第一层（若日常增量已常态执行，此层只查漏）：**
1. 核对产物全部归档、SHA 在册。
2. 运行态登记刷新到此刻（在途项标明"移交后由谁处理或等待"）。

**第二层（离场收口，7 项）：**
1. 写**接续点横幅**：现状一句话 + **作废清单**（哪些旧结论/数字已失效不得引用，逐项列）。
2. 更新产物索引与阅读顺序（接管方第一小时要读什么，按序列出）。
3. 未验证清单收口：本轮新产生的未验项入册，标 `[未验]`。
4. 授权与部署记录落盘（越权动作的用户授权原话 + 时刻 + 回滚路径）。
5. 外部承诺收口：open issue / PR / 待回复项清单（URL + 期望动作）。
6. 新增节自检（标题查重、与既有节 diff 查重复粘贴）+ 全文空节扫描一次（扫描器先对已知好节校验自身无误报再采信）。
7. 定稿时刻记全文 SHA + 时间戳 + **组织形式登记**（见 §四）。

**移交完成判据**：交接包 11 必含项（§四）全部在盘、可被陌生人按索引找到；在台账/工作文档追加"移交记录"节（时刻 + SHA + 一句话现状）。

## 三、接管手续（触发后执行；第 0 步必须最先做）

**第 0 步：分级自判（fail-closed，通用）**
- 逐字复述三要素：①接续点横幅 ②作废清单 ③产物谱系（构建/交付物的 SHA 与状态）。
- **任一答不全 ⇒ 一律按冷交接全套执行**（上下文被压缩过的会话按冷交接处理——压缩摘要可能保留旧数字而丢掉作废横幅，比零上下文更危险）。

**冷交接：7 项机械验证（全部留原始命令/输出摘要，否则"通过"不可审计）**
1. **SHA 核对 + 语义对账**：关键文件 hash 与交接记录比对，且每项附一句"内容确为所述状态"——SHA 防篡改不防失实。
2. **作废项 grep（扩面）**：对工作文档 + 全部产物 grep 作废词；每项作废反向校验"替代结论存在且未被再作废"。
3. **验收/结论文件抽查**：抽 2-3 份，核对强度标注与所引 SHA 对得上谱系。
4. **运行面快照**：资源租约 + scheduled tasks + 后台 job + 常驻进程/端口，四项。
5. **工具面枚举 + 最小探活**：枚举在注册工具；对交接包声称可用的外部通道各做一次最小调用（注册 ≠ 能用）。
6. **空节扫描（先校验扫描器）**：对 ≥3 个已知好节先跑扫描器确认无误报，再全文扫；发现空节报告而非臆测。
7. **读移交方运行态登记**：在途项按登记处理（等待或接手），不盲目开跑。

**温交接**（自判三要素完整复述通过）：验证项 1/2/6 + 增量抽验，其余可引用上一包。

**完成判据**：追加"接管确认轮"记录（谁、何时、每项验证的原始输出摘要、发现缺口清单）→ **先宣布"已接住/缺口 X"再开工**。

## 四、交接包 11 必含项（移交方产出物 / 接管方核对物）

| # | 项 | 没有它会怎样 |
|---|---|---|
| 1 | 接续点横幅 + 作废清单 | 引僵尸结论（实证：21/32 数字事故） |
| 2 | 产物谱系 + SHA + 归档路径 | "记忆里有盘上没有"= 不存在（6E9E599D 教训） |
| 3 | 证据强度标注体系 | 未验项被当定稿引用 |
| 4 | 未验证清单（"不得当作结论"） | 重复踩坑 |
| 5 | 判据及其有效环境（被废除的留废除记录） | 旧环境门槛误判新环境 |
| 6 | 下一步最小动作（"定位前不做什么"） | 接管方乱开战线 |
| 7 | 环境/工具面快照（含**插件/bundle 版本 pin**） | 新会话工具面静默失真 |
| 8 | 授权记录 + 凭据现状（各外部通道最近探活结果） | 无法判断哪些动作可重做；撞失效凭据 |
| 9 | 回滚路径（脚本/归档 + 前置校验） | 只能前进不能后退 |
| 10 | 运行态登记 | 撞在途轮次 → 整轮作废（实证：两次 VOID） |
| 11 | **组织形式登记** | 沿用断裂——下一任不知道该跟谁合作、用什么规则裁决 |

**第 11 项内容规范**（治"开发组织形式能被沿用"）：
- 角色表：谁是 Lead / 谁做实现 / 谁做测量 / 谁做审查（实现 ≠ 测量 ≠ 审查 铁律）；
- 协作花名册：成员名 + 当前职责 + 联系/派单方式；
- 裁决规则：通过/降级/废除由谁裁定、依据什么文档（指向 GOVERNANCE 式文件）；
- 对外接口：已建立的贡献渠道（上游仓库、issue 模板）、共享资源（锁根、发布仓库、凭据现状）。
